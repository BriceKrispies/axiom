# Axiom dylint ratchet baseline — read by scripts/dylint-gate.sh (CI + local).
# Format: <lint_name>=<max allowed findings>
# The dylint gate fails only if a run raises a lint above its baseline.
#
# IMPORTANT: the size lints (functions/impl-blocks) fire on exactly two sanctioned
# spine items plus (for the unitless-float lint) one GPU-output float. The
# Branchless Law is at ZERO on the spine (crates/ + modules/, non-test) — verified;
# engine_no_branching now scopes off the exempt tiers (apps/, games/, tools/,
# xtask), so it stays at 0 and any NEW spine branch trips the gate immediately.
#
# A spine regression still trips the gate: a layer/module crate that today emits
# no finding would add a NEW one, pushing the count above these baselines. Drive
# the spine to 0.
#
# The two `engine_no_large_functions` are two pre-existing spine fns >120 lines
# (axiom-render-pipeline::render_pipeline_api and axiom::scene_commands); the two
# `engine_no_large_impl_blocks` are axiom-math's 4x4-matrix impl block and
# axiom-physics::PhysicsWorld (32 items; grown pre-existing by the gravix half-pipe
# work — a god-object smell to split later); the one
# `engine_no_unitless_float_public_api` is FrameOutcome's render-float intensity
# multiplier (GPU output data).
#
# `engine_no_retained_state` (the Axiom State Law) is DELIBERATELY ABSENT from this
# file. It is a zero-tolerance architectural law, not a ratchet: a missing entry
# means the gate allows zero findings, so the gate FAILS on this lint today, on
# purpose. The engine currently has 787 violations, inventoried in
# docs/audits/retained-state-audit.md — that is a migration work list, NOT an allowed
# baseline. Do not add an `engine_no_retained_state=N` line here to make the gate
# pass; remove the retained state instead. See
# tools/lints/engine_no_retained_state/README.md.
#
# `engine_no_unwrap_or` (added 2026-08-14) bans `.unwrap_or(..)` in non-test spine
# code: a value-level branch `engine_no_branching` cannot see (no if/match in the
# HIR), and an eagerly-evaluated default chosen at the USE site, which is where
# absence gets papered over. The first full run found **211 distinct call sites
# across 36 spine crates/modules** (native build — `axiom-windowing`'s wasm32 arm
# and `axiom-gpu-backend`'s `offscreen` feature are compiled out, so the true
# total is higher). Biggest holders: axiom-text 35, axiom-canvas2d-backend 24,
# axiom-sim-core 13, axiom-planetgen 12, axiom-hydrology 11.
#
# The number below is 36, not 211, because of how this gate counts: it greps the
# `#[warn(<lint>)] on by default` note, which rustc prints ONCE PER COMPILATION
# UNIT, not once per finding. So every baseline in this file is really "units
# emitting the lint" (for the pre-existing entries the two happen to coincide).
# That makes this a coarse ratchet — a NEW `unwrap_or` in an already-flagged
# crate will not trip it. Driving a crate to zero should be followed by lowering
# this number. Fixing the gate to count findings needs a
# `--message-format=json` rewrite of scripts/dylint-gate.sh.
#
# History (pre-CI, when this gate ran as .git/hooks/pre-commit):
#   2026-06-26: engine_no_large_files 2 -> 0 (six over-budget spine files split
#     into private submodules — pure relocation, facade/coverage/branchless kept).
#   2026-07-04: engine_no_branching 18 -> 0 (lint scoped off the Branchless-Law-
#     exempt tiers + resolves each branch to its macro call site).
#   2026-07-04: the gate moved off the pre-commit hook into CI (scripts/dylint-gate.sh).
engine_no_branching=0
engine_no_unwrap_or=36
engine_no_large_files=0
engine_no_large_functions=2
engine_no_large_impl_blocks=2
engine_no_unitless_float_public_api=1
